# BLE 전송 간격 수정 2차

기준 커밋: `0e87f4a20c742c6e62c99b482f2813d99d6ee396`.

## 확인한 현상

- 양쪽에 기준 펌웨어를 적용한 사용자가 BLE에서 거친 이동과 포스터치 이후 악화를 보고했고, USB 출력에서는 사라진다고 확인했다.
- Windows에서 실제 연결 간격 15ms, 지연 허용값 0, 송수신 2M PHY를 읽었다. 따라서 기존 지연 허용값 변경은 이미 적용됐다.
- Toucan 마우스만 Windows Raw Input으로 기록했다. 시작 안내 후 연속 이동 구간(기록 12~24초)의 이동 보고 간격 중앙값은 30.033ms, 95백분위 45.157ms, 최대 315.750ms였다. 사용자가 연속 이동과 증상을 확인했다.
- 이 수치는 PC 입력 도착 간격이며 손가락 움직임부터 화면 표시까지의 지연 측정이 아니다. 긴 이동 공백 중에도 변위 0 보고가 있어 완전한 무선 단절로 단정할 수 없다.
- 기존 송신기는 한 알림의 완료 콜백까지 다음 알림을 제출하지 않는다. LCD와 송신 스레드는 모두 우선순위 5이며 타임슬라이스 크기는 0이었다.

## 변경

- BLE에 최대 두 알림을 제출할 수 있게 한다. 완료를 기다리는 동안 다음 연결 이벤트용 데이터를 준비하되, 미전송 이동은 기존 제한된 큐에서 합친다.
- 연결 종료와 뒤늦은 완료 콜백은 세대 토큰으로 구분한다. 중복 완료가 전송 허용량을 늘리지 않는다. 클릭 누름/해제 순서를 유지한다.
- LCD 작업 우선순위만 10으로 낮춰 BLE 전송(5)이 먼저 실행되게 한다. 화면 디자인과 센서·클릭·드래그 동작은 바꾸지 않는다.
- 실제 기기에서 이번 변경의 개선 효과와 포스터치 이후 증상 해결 여부는 적용 후 재측정해야 한다. 무선 간섭이나 PHY 문제를 원인으로 확정하지 않았다.

## 검사

기존 이동/클릭 큐 검사에 두 건 제한, 연결 세대 교체, 중복 콜백, 완료 순서, 315ms 지연 중 더블클릭 순서 보존을 추가했다. 15ms 연결/완료 한 이벤트 지연 모델로 단일 알림 대기와 두 알림 제출의 처리량을 비교한다. 모델의 처리량은 실제 하드웨어 측정값이 아니다.
