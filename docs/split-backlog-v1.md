# 오른쪽 입력 전송 적체 방지

기준: 4854841439f8fbb8dd82e2955bd99dc88cac6e75.

## 실기기 보고 및 진단의 한계

사용자는 양쪽 force-repeat-diagnostics 적용 후에도 포스터치 더블클릭과 세 손가락 가운데 탭이 되지 않고, 커서가 약 1초 뒤에 움직이다가 점차 실시간으로 따라온다고 확인했다. 이는 이동량 감소라는 앞선 해석을 바로잡은 것이다.

2026-09-17 01:54 UTC 기록은 PC 입력 794건, 이동 743건, 도착 간격 중앙값 15.068ms였다. 움직임과 클릭이 섞였으며, 이 도착 간격은 손가락부터 화면까지의 지연을 나타내지 않는다. 동시에 읽은 왼쪽 진단에서 BLE 오류/재시도는 0, 대기열 깊이는 0~1, 부팅 후 최대 깊이는 2였다. 따라서 이 대기열이 비었다는 사실만으로 전체 입력 지연이 없다고 결론 낼 수 없다. 뒤이은 재발 시점에도 같은 왼쪽 수치는 정상이었다. 원인이 실기기에서 확정되었다고 주장하지 않는다.

## 수정한 전송 경로

ZMK v0.3의 input_split.c는 오른쪽 입력 콜백에서 zmk_split_peripheral_report_event를 호출하고, Bluetooth service.c는 각 축과 버튼 이벤트마다 bt_gatt_notify를 호출한다. 기존 왼쪽 HID 수정은 이 오른쪽 경로의 대기를 제한하지 않았다.

Toucan 입력(reg 0)만 별도 송신 스레드로 넘긴다. 입력 콜백은 대기하지 않으며 X/Y는 완성된 프레임 단위로 합친다. 버튼/접촉/진단 경계를 넘어 합치지 않고, 전송을 시작한 X의 Y는 다른 프레임과 합치지 않는다. Bluetooth에 완료를 기다리는 입력 이벤트는 최대 두 개다. 정지 후 40ms 넘은 대기 이동은 재생하지 않지만, 버튼 이벤트는 오래되어도 보존한다. 버튼 위주의 비정상적 큐 넘침에는 버튼 5개와 접촉을 먼저 해제하여 눌림 고정을 피한다. 키보드 키와 다른 입력 장치는 기존 경로를 사용한다.

왼쪽 펌웨어 및 split wire format은 그대로다. 오른쪽의 최대 큐 대기/notify 호출/완료 시간을 기존 진단 값 상위 16비트로 추가한다. source_strength_flags의 bit31이 이 확장 형식을 표시하고 bits29~30은 큐 깊이(min(depth,3))다. last_press_strength 상위16은 notify 최대시간, last_release_strength 상위16은 완료 최대시간, source_baseline 상위16은 큐 최대시간이다. 하위16의 세기/기준값은 유지한다. 추가 무선 이벤트 없이 기존 11개 값 안에서 보낸다.

## 클릭 수정

첫 클릭을 해제한 위치에서 각 축 12 센서 단위까지는 두 번째 누름을 위한 미세 흔들림으로 허용한다. 이 범위에서는 클릭 위치를 유지한다. 400ms가 지나거나 범위를 벗어나면 반복 클릭 보조가 끝나며, 범위를 벗어난 그 프레임부터 일반 이동으로 복귀한다. 범위를 벗어나기 전에 시작했던 낮은 역치 후보도 취소한다. 이 한정된 공간 허용은 의도적인 아주 작은 이동과 손가락 변형을 완벽히 구별하지 못하므로 실기기 평가가 필요하다. 범위 밖 일반 이동에 시간 지연은 추가하지 않는다.

세 손가락 탭의 유효성은 첫 손가락 슬롯의 접촉 면적과 분리한다. IQS5xx는 손가락의 메모리 슬롯을 고정하므로 먼저 닿은 손가락을 먼저 떼면 첫 슬롯은 비어도 다른 손가락은 남을 수 있다. 세 손가락 탭에 별도의 300ms/48 센서 단위 허용치를 둔다. 손바닥/과다 접촉은 계속 거부한다. 센서가 허용하는 손가락 수가 3 미만이면 0x066A를 3으로 설정하고 읽어 확인한다. 기기의 원래 값이 실제로 2였는지는 측정하지 않았다.

LCD 그림, 정렬, 해상도, 필터, 커서 감도, 첫 포스터치 역치, PC BLE 연결 설정은 변경하지 않는다.

## 검증

호스트 검사: 10분 연속 이동(8~128ms 소비 간격), 정지 후 재생 방지, 전송 중 X/Y 경계, 클릭 4개 에지 보존, 가운데 클릭 보존, 오래된 Y의 동기화, 넘침 해제, 끊긴 연결의 늦은 콜백, 미세 이동을 동반한 두 번째 누름, 반복 클릭 범위에서 이탈한 뒤 정상 이동, 실제 드라이버의 유효성/포스터치 소비 판정을 포함한 세 손가락 순차 해제.

실제 약 1초 지연과 실제 더블클릭/가운데 클릭 해결은 새 오른쪽 펌웨어 적용 후 별도로 확인해야 한다.
