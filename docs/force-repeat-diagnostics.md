# 연속 포스터치 수정과 지연 진단

기준 커밋: 5cf0db68220aa1ceaf77e3231e2e36e256c7bf50.

## 확인한 사실

사용자는 첫 클릭 강조가 유지되어 더블클릭이 되지 않는다고 보고했다. 기존 코드를 검사한 결과, 클릭 확인 직후 60 센서 단위의 위치 변화만으로 드래그가 고정되고 다음 이완/누름이 클릭으로 나오지 않는 경로를 재현했다. 이 입력은 합성 재현이며 사용자 센서 원시값을 기록한 결과는 아니다.

별도의 PC 측정에서 이동 보고 간격 중앙값은 29.571ms, 실제 연결 간격은 15ms/latency 0/2M PHY였다. 사용자는 마지막에 클릭 강조가 풀렸는데도 계속 움직이는 커서가 매우 느려졌다고 확인했다. 따라서 후반 지연을 클릭 고정 하나로 설명하지 않는다. 20초 기록은 이동과 클릭 동작을 섞었으므로 전체 최대 공백 2725ms를 순수 통신 지연으로 단정하지 않는다.

## 클릭 수정

- 첫 클릭 역치는 정지 30/8%, 이동 90/24% 그대로다.
- 클릭 해제에는 최고값에서 별도 해제 폭(16 또는 접촉 기준의 3% 중 큰 값)만큼 내려가는 조건과 기존 16ms 지속 확인을 쓴다.
- 해제 후 400ms 이내, 의도적 이동이 없으면 이완 최저값에서 동일한 해제 폭만큼 다시 올라오는 것으로 다음 클릭을 판정한다. 손을 떼거나 이동하거나 시간이 끝나면 일반 클릭 기준으로 돌아간다. 작은 흔들림과 한 프레임의 상승/하강은 클릭하지 않는다.
- 드래그는 클릭 후 300ms 유지한 다음 새로 48 센서 단위 넘게 이동하면 시작한다. 그 이전에 생긴 위치 변화는 드래그에 누적하지 않는다. 시작된 드래그는 유효한 단일 접촉 동안 압력 저하로 풀리지 않는다.
- 커서의 일반 이동을 지연시키는 대기열이나 타이머를 추가하지 않는다. 누른 동안에는 사용자가 요청한 클릭 위치 고정이 적용된다.

## 진단

센서 프레임/원시 이동량/억제된 이동량/최근 클릭 세기/기준값을 오른쪽에서 계수한다. 진단 전송은 동기화하지 않은 전용 ABS 코드이고, 100ms마다 최대 한 이벤트만 비차단으로 제출한다. 시작/종료 순번과 모든 항목을 확인한 완전한 묶음만 왼쪽에서 사용한다.

왼쪽에서는 수신 이동량, HID 입력량, BLE 제출량, 완료 콜백, 재시도, 큐 깊이와 지연 최대값을 계수한다. 읽기 전용 암호화 GATT 특성으로 명시적으로 조회할 때만 PC에 반환하며 알림 스트림은 만들지 않는다. 기존 HID 서비스 뒤에 추가하여 기존 핸들/보고서 형식을 유지한다. 아이콘은 변경하지 않는다. BLE 속도 관련 설정은 바꾸지 않는다.

서비스 UUID: 0ed291b0-9e1a-4f35-a02d-75e470bf0601. 특성 UUID: 0ed291b1-9e1a-4f35-a02d-75e470bf0601. 형식은 diagnostics.h의 40개 uint32_t 리틀엔디언 값이다. 소스 시각과 왼쪽 수신 시각은 다른 부팅 시계를 쓰므로 직접 빼지 않는다. 최대값은 부팅 이후 값이므로 정상/이상 구간 전후 스냅샷의 누계 차이와 함께 해석한다.

## 검증 범위

동작 검사는 새 조기 드래그 재현, 작은 폭의 연속 누름, 잡음/시간 만료/이동 후 취소, 0.3초 홀드, 드래그 유지/복구, 진단 이벤트 유실을 포함한다. 실제 더블클릭 성공 및 지연 해결은 아직 검증하지 않았다. 새 진단 펌웨어를 양쪽에 적용한 뒤 수치로 확인해야 한다.
