# 포스터치 클릭

오른쪽 트랙패드에서 손가락을 가볍게 올린 뒤 힘을 더 주면 좌클릭을 누른
상태가 됩니다. 누름 판정 중에는 커서 이동을 보내지 않고, 클릭 후 작은 흔들림도
무시합니다. 누른 채 설정 거리 이상 움직이면 드래그를 시작하며, 힘을 빼거나
손가락을 떼면 해제합니다. 두 손가락 탭의 우클릭과 두 손가락 스크롤은 유지합니다.

## 설정

`boards/shields/toucan/toucan_right.overlay`의 `tps43_trackpad`에 적용되어 있습니다.

| 항목 | 초기값 | 의미 |
|---|---:|---|
| `force-click` | 활성화 | 터치 강도로 좌클릭 처리 |
| `force-click-threshold` | 40 | 누름 증가량의 최소값 |
| `force-click-release-threshold` | 20 | 해제 증가량의 최소값 |
| `force-click-threshold-percent` | 12 | 기준값 대비 누름 증가율(%) |
| `force-click-release-threshold-percent` | 6 | 기준값 대비 해제 증가율(%) |
| `force-click-baseline-ms` | 80 | 접촉 강도와 위치가 안정된 상태에서 기준값을 측정하는 시간 |
| `force-click-debounce-ms` | 32 | 누름·해제 기준을 연속으로 만족해야 하는 시간 |
| `force-click-settle-ms` | 120 | 처음 접촉한 뒤 클릭 준비까지의 최소 시간 |
| `force-click-motion-threshold` | 16 | 클릭 전에 이 거리보다 움직이면 기준값 재측정 |
| `force-click-drag-threshold` | 64 | 누름 후보 위치에서 이 거리보다 움직이면 드래그 시작 |

판정에는 현재 터치 강도에서 보정된 기준값을 뺀 증가량을 사용합니다. 누름은
`max(40, 기준값의 12%)`, 해제는 `max(20, 기준값의 6%)`를 적용합니다.
예를 들어 기준값이 1000이면 120 이상 증가한 상태가 32ms 유지되어야 누르고,
증가량이 60 이하인 상태가 32ms 유지되면 해제합니다. 직전 보고와의 차이는 아닙니다.

접촉 직후 강도가 계속 변하거나 클릭 전에 위치가 설정 거리보다 이동하면
기준값을 다시 측정합니다. 이후 누르지 않은 동안에는 기준값이 천천히 보정되며,
힘을 뺄 때는 더 빠르게 내려갑니다. 누름 후보 및 클릭 유지 중에는 기준값을
고정하여 누르고 있는 힘이 새로운 기준값으로 흡수되지 않게 합니다.

누름 후보 동안, 클릭 후 드래그 시작 거리 안에서, 그리고 해제 판정 중과
해제 직후 32ms 동안에는 커서 이동값을 버립니다. 나중에 합산하여 보내지 않습니다.
드래그가 시작된 뒤에는 시작 위치로 돌아와도 다시 커서를 고정하지 않습니다.
거리값은 센서의 X 또는 Y 좌표 단위이며 화면 픽셀이 아닙니다.

임계값은 실기기 측정 전의 시작값이며 물리적인 압력 단위가 아닙니다. 강도 증가가
전혀 없거나 센서값이 이미 포화된 접촉은 이 판정으로 구분할 수 없습니다.
이동 중 접촉 변화와 누르는 동작을 모든 경우에 구분하는지는 실기기 확인이 필요합니다.

한 손가락 탭 클릭은 꺼져 있으며, 한 손가락 좌클릭은 포스터치로만 처리합니다.
포스터치가 켜져 있으면
시간 기반 길게 누르기는 비활성화하여 접촉 시간만으로 클릭하지 않습니다.
두 손가락이 닿으면 진행 중인 포스터치 클릭을 해제하고, 모두 뗄 때까지 새로운
포스터치 판정을 막아 스크롤 종료 중의 오클릭을 방지합니다.

## 정지 상태의 감지

손가락 접촉 중에만 센서의 이벤트 전용 모드를 해제하여 좌표가 바뀌지 않아도
터치 강도를 계속 읽습니다. 손가락을 떼면 이벤트 모드로 복귀합니다.
활성 상태 및 정지 접촉 상태의 보고 간격을 8ms로 설정하고, 정지 접촉 중에는
더 낮은 감지 모드로 넘어가지 않도록 설정했습니다. 따라서 손가락을 계속
올려놓고 있을 때의 전력 사용량은 기존 설정과 달라질 수 있습니다.

손가락 제거·다중 터치·잘못된 센서 데이터·통신 오류·절전 전환 때 버튼을 해제합니다.
버튼을 누른 상태에서 250ms 동안 새 센서 보고가 없으면 감시 타이머도 버튼을 해제합니다.

## 검증

### LCD 표시

현재 모디 줄 높이(y=78~101)에 Win·Alt·Ctrl·Shift 아이콘을 고정 배치하고,
누르지 않은 모디는 윤곽선, 누른 모디는 같은 모양의 내부를 채워 표시합니다.
왼쪽·오른쪽 모디키는 각각 같은 종류의 아이콘에 반영합니다.

줄 오른쪽(x=104~127)에는 숫자 대신 24×24 픽셀의 손가락 아이콘이 표시됩니다.

| 센서 상태 | 표시 |
|---|---|
| 손가락 없음 | 손가락 윤곽선 |
| 가벼운 접촉 또는 클릭 준비 중 | 채워진 손가락 |
| 포스터치 클릭 인식 및 유지 | 채워진 손가락 + 후광 |

후광은 단순한 접촉 강도 상승이 아니라 실제 버튼 누름 판정과 연결됩니다.
이동 중 강도가 달라져도 클릭으로 판정되지 않으면 일반 접촉 아이콘을 유지합니다.
화면은 최대 50ms 간격으로 상태 변화를 반영합니다. 오른쪽 센서는 상태 변화 시
즉시, 접촉 유지 중에는 250ms 간격으로 상태를 전달합니다. 750ms 이상 새 상태가
없으면 LCD는 손가락 없음으로 되돌립니다.

표시 전용 값은 기존 split input 경로의 전용 ABS 코드 `0x18`로 전달하며,
마우스 보고를 발생시키지 않도록 `sync=false`를 사용합니다.
이번 표시를 사용하려면 왼쪽과 오른쪽 펌웨어를 모두 같은 버전으로 갱신해야 합니다.

### 자동 검사와 실기기 확인

`tests/force_click_test.c`는 초기 접촉 강도의 상승, 장시간 가벼운 접촉,
이동 중 강도 변화, 힘을 뺀 뒤의 기준값 보정, 크기가 다른 접촉 강도,
누름 판정 중의 미세 이동, 드래그 시작 및 유지, 해제 및 재클릭,
다중 터치, 데이터 중단 및 16비트 경계를 검사합니다.
GitHub Actions가 이 검사를 통과한 뒤 기존 펌웨어 빌드를 실행합니다.

실기기의 강도 구분 정확도와 최적 임계값은 아직 측정하지 않았습니다.
실기기 확인 순서는 커서 이동 → 멈추고 가볍게 접촉 유지 → 손가락을 떼지 않고
꾹 누르기 → 클릭 중 미세한 흔들림 → 의도적인 드래그 → 힘 빼기 → 재클릭 →
손가락 떼기 → 두 손가락 스크롤입니다.

## 되돌리기

`force-click;`를 제거하고 기존 `single-tap;`, `press-and-hold;`,
`hold-time = <500>;`를 복원하면 기존 클릭 방식으로 돌아갑니다.
추가한 `report-rate-active`, `report-rate-idle-touch`, `timeout-idle-touch`도
제거하면 센서 기본 보고·절전 설정을 다시 사용합니다.
