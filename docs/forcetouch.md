# 포스터치, 프레스 홀드 및 BLE 입력

## 클릭과 더블클릭

포스터치는 안정 접촉 기준보다 강도가 8% 또는 30 이상 증가하고 16ms 유지되면
누름을 보냅니다. 강도 증가가 3% 또는 16 이하가 되면 16ms 확인 뒤 해제합니다.
물리적인 압력 단위가 아니라 센서의 접촉 강도 증가량입니다.

누름 기준에 도달하기 전 약 1/3 수준의 강도 증가부터 좌표를 버립니다.
클릭까지 이어지지 않는 약한 누름은 80ms까지만 보호합니다.
클릭 확정 후 180ms 동안은 옆으로 밀려도 커서를 움직이거나 드래그를 시작하지
않습니다. 그 뒤의 위치를 새 기준으로 삼아 24 센서 단위를 넘어 이동하면 드래그합니다.
버튼 누름 자체를 180ms 늦추는 것은 아닙니다.

드래그 없이 힘을 뺐으면 250ms 동안 해제 위치에서 64 센서 단위 이내의 움직임을
버립니다. 이 구간에는 접촉 기준값을 다시 잡거나 좌표 변화로 다음 누름을 막지 않습니다.
손을 떼지 않고 누름 → 힘 빼기 → 다시 누름으로 두 번 클릭할 수 있습니다.
64 단위를 넘어 의도적으로 이동하면 대기 시간 전에 일반 이동으로 돌아갑니다.
억제했던 이동량은 나중에 재생하지 않습니다. 더블클릭의 최종 시간 판정은 운영체제가 합니다.

일반 탭은 200ms 이내, 최초 접촉에서 16 센서 단위 이내의 접촉을 뗄 때 클릭합니다.
탭 후보의 작은 좌표 이동은 버리므로 일반 더블탭도 커서가 밀리지 않게 합니다.
범위를 넘어 움직이면 타이머를 기다리지 않고 이동으로 전환합니다.
포스터치나 프레스 홀드를 사용한 접촉에서는 손을 뗄 때 추가 탭이 나오지 않습니다.
두 손가락 탭과 스크롤은 유지합니다.

## 약 0.5초 프레스 홀드

힘을 주지 않고 처음 댄 위치의 16 센서 단위 안에서 500ms 유지하면 왼쪽 버튼을
누른 상태로 전환합니다. 이후 24 단위를 넘게 움직이면 드래그하며, 손을 떼면 해제합니다.
500ms는 tap-time 200ms + hold-time 300ms입니다.

처음부터 이동한 접촉에서는 시간만 지났다고 드래그로 바뀌지 않습니다.
포스터치 판정이 시작된 접촉에서도 별도의 시간 기반 누름을 중복 발생시키지 않습니다.
센서 내장 탭/홀드의 상대 좌표 지연을 피하기 위해 두 동작은 펌웨어에서 처리합니다.

## BLE 전달

접촉 중 센서 보고 간격은 8ms입니다. X/Y 이동을 하나의 32비트 값으로 묶어
한 번에 전송하고 왼쪽에서 기존 입력 처리기에 복원합니다. 대각선 이동의 오른쪽→왼쪽
알림 수는 프레임당 2건에서 1건으로 줄어듭니다. NAV/NUM 처리와 이동 배율은 유지합니다.
상태 표시 코드는 ABS 0x18, 묶은 좌표 코드는 ABS 0x19입니다.

PC 연결의 선호 간격은 7.5ms로 요청하고 연결 이벤트 건너뛰기 허용값은 0으로 설정합니다.
분할 키보드 사이도 건너뛰기 허용값을 0으로 설정합니다. PC가 실제로 채택하는 연결
간격은 호스트에 달려 있습니다. PC로 보낼 마우스 보고 큐는 20개에서 4개로 줄입니다.
절전보다 입력 응답을 우선하므로 BLE 대기 전력은 늘어날 수 있습니다.

센서 작업은 별도 큐에서 처리하며, 프레임 읽기 직후 센서 통신 창을 닫습니다.
입력 등록 대기는 최대 5ms이고 무한히 시스템 작업 큐를 막지 않습니다.
250ms 센서 감시와 750ms 중앙 접촉 감시, 잃어버린 버튼 해제 복구를 유지합니다.
프레스 홀드도 손 떼기·다중 터치·통신 오류·보고 중단에서 해제합니다.

## LCD와 적용

아이콘 파일, 크기, 위치, 정렬은 변경하지 않습니다. 손가락 상태는 실제 버튼 누름을
반영하므로 시간 기반 프레스 홀드 중에도 누름 상태가 표시됩니다.

좌표 통신 형식이 바뀌므로 이번 버전은 왼쪽과 오른쪽을 모두 갱신해야 합니다.
왼쪽을 먼저, 이어서 오른쪽을 갱신합니다. 설정 초기화 펌웨어는 사용할 필요가 없습니다.

## 검증

검사는 착지·잡음·이동 후 누름·움직이며 클릭·누름 사이 좌표 흔들림·짧은 클릭의
드래그 전환 금지·연속 두 번 누르기·일반 더블탭·0.5초 홀드·홀드 해제·다중 터치·
센서 중단·16비트 양축의 압축/복원·TP 레이어 및 버튼 해제 복구를 다룹니다.
호스트에서 같은 C 판정 코드를 실행하고 ASan/UBSan 검사 후 좌우 펌웨어를 빌드합니다.
실제 BLE 보고 간격과 체감 개선 여부는 실기기에서 확인해야 합니다.
