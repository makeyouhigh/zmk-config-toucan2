# v21 포스클릭 우선 판정

포스클릭은 버튼 누름·해제를 한 쌍으로 출력하며 드래그로 전환하지 않습니다. 250ms 정지 후 이동하는 홀드 드래그는 별도 기능입니다. 포스클릭 준비가 시작되면 해당 접촉의 홀드를 취소하고, 손을 완전히 뗀 다음 접촉부터 홀드를 다시 허용합니다. 250ms가 지난 보고에서 강도 상승과 좌표 이동이 함께 들어와도 포스클릭 준비를 먼저 검사합니다. 이미 시작한 홀드 드래그는 이탈까지 유지됩니다.

## 빠른 연속 누름

v20 실측에서는 두 봉우리 사이 하강이 23~170에 그쳐 기존 200 조건을 통과하지 못하는 사례가 반복됐습니다. v21은 최초 누름의 200 상승과 클릭의 고정 절대 기준을 유지하면서, 클릭 완료 조건을 분리합니다.

□ 최고값보다 20 이상 내려가면 하강 확인을 시작합니다. 16ms 유지하면 클릭을 완료합니다. 그동안 최고값과의 차이가 10 미만으로 회복되면 확인을 취소합니다. 한 보고만 튀었다 복구된 경우에는 클릭을 추가하지 않습니다.

□ 200 이상 하강하거나 저장된 해제값 이하로 내려가면 기존처럼 즉시 완료합니다. 손을 떼면 아직 확정된 누름이 있을 때 한 번만 완료합니다.

□ 완료 뒤 500ms 안에는 새 최저값에서 100 이상 상승하고 고정 클릭값 이상에서 8ms 유지하면 다음 누름으로 인정합니다. 시간 창이 끝나면 상승 200을 적용합니다. 고정 클릭값을 낮추거나 첫 접촉 세기에 따라 바꾸지 않습니다.

□ 작고 짧은 반복 상승은 확인되기 전까지 커서 이동을 억제하지 않습니다. 기존 120ms 이동 억제 상한을 유지하고, 억제한 이동을 저장하거나 뒤늦게 전송하지 않습니다. 새 대기 작업·이벤트 큐·전송 제한은 추가하지 않습니다.

## 검증과 한계

2026-09-18에 사용자가 두 번씩 눌렀다고 확인한 네 센서 기록의 전체 샘플을 사용자 PC의 v20-double20-fixtures에만 보존했습니다. 원시 자료는 외부 저장소에 업로드하지 않습니다. 기록의 시간·강도·손가락 수·좌표·유효 여부와 각 구간의 실제 설정을 변경 없이 실제 판정 함수에 입력합니다. PC 장치 식별자나 다른 입력은 포함하지 않습니다.

수동으로 구분한 20개 두 봉우리 구간 중 19개에서 두 클릭이 생성되고 간격은 159~271ms입니다. 나머지 한 구간은 첫 봉우리가 3687로 당시 고정 클릭값 3700보다 작아서 한 클릭으로 남습니다. 이 기준을 몰래 낮추거나, 센서 근거 없이 두 클릭을 만들어내지 않습니다.

신호 전과 구분한 구간 밖에서 생성된 클릭은 6회이며 의도가 확인되지 않았습니다. 이를 성공이나 오클릭으로 임의 분류하지 않습니다. 따라서 위 수치는 기록 재생 결과이지 실기기 성공률이나 오클릭이 없다는 보장이 아닙니다. 새 펌웨어에서 PC의 실제 더블클릭 인식과 커서 위치, 일상 이동 중 오클릭은 적용 후 확인할 항목입니다.

재생 방법: tests/force_trace_replay.c를 컴파일한 뒤 python tests/force_trace_replay_test.py 실행파일 로컬자료폴더 명령으로 실행합니다. GitHub CI는 원시 자료 없이 합성 입력 검사와 메모리 오류 검사를 수행합니다.

추가 검사에는 23 단위의 얕은 골짜기, 한 프레임 하강과 반복 잡음, 두 번째 누름의 작은 상승, 시간 창 종료, 강도와 이동이 같은 보고에 들어오는 홀드 경계, 높은 강도 장기 유지, 버튼 해제·이탈·오류 복구가 포함됩니다. 기존 탭·세 손가락 탭·LCD·BLE 전송 구현은 변경하지 않습니다.

오른쪽만 기능 변경 대상입니다. 빌드 산출물과 해시는 FIRMWARE_VERSIONS.md에 별도로 기록합니다.
